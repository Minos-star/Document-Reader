## 3. 关键发现（这是笔记的核心，每条都要有证据）

### 发现 1：固定分块会切断 Q&A
- 证据：Chunk 0 结尾是 "Q4: 睡眠模式会不会影响净化效果？ A:"
- 影响：问题和答案分属两个块，检索可能只命中一半，答案残缺
- （再贴你发现的其他案例：CADR 被切断、日期被切断）

### 发现 2：递归分块初版的"碎片化"问题
- 只做降级不做合并 → 16 个碎块，37 字的标题块无法被检索
- 教训：递归 = 降级拆分 + 贪心合并，两步缺一不可

### 发现 3：合并时丢失段落边界（bug 记录）
- 现象：buf += unit 直接拼接，"400-800-5678" + "5. xxx" → "400-800-56785. xxx"
- 修复：拼接处加 "\n\n"
- 这类"踩坑-修复"记录是面试素材：能讲清楚 bug 成因和修复思路

### 发现 4：截断指标会误报
- "结尾是标点"只是"边界干净"的近似：列表项 "...请联系客服 400-800-5678" 无标点但语义完整
- 启示：自动化指标需要人工抽查校准 → 这就是明天建评测集的原因

## 4. 今日结论（3 句话版）
1. 固定分块 vs 递归分块的区别：字符中心 vs 语义单元中心
2. 适用场景：无结构文本/原型 vs 企业结构化文档（我的场景）
3. 分块无绝对优劣，要靠评测数据说话
